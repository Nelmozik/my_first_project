1. Рабочая директория — где редактируются файлы, индекс — подготовленные к коммиту изменения, репозиторий — хранилище истории коммитов.
2. git add — переносит изменения в индекс; git commit — сохраняет их как новую точку истории; git push — отправляет коммиты на удалённый репозиторий.
3. Информативные сообщения помогают понять суть изменений без анализа diff, что упрощает работу в команде и поиск нужных коммитов.
4. git add имя_файла добавляет только конкретный файл, git add . — все изменения сразу. Первое удобно для раздельных коммитов, второе — когда все изменения относятся к одной задаче.
5. git status показывает состояние файлов: untracked, staged, изменённые. Вывод меняется по мере выполнения add/commit.
6. git remote add origin URL связывает локальный репозиторий с удалённым; origin — условное имя основного удалённого репозитория.
7. Флаг -u связывает локальную и удалённую ветку, чтобы дальше использовать просто git push/pull без указания origin и имени ветки.
8. Ветка по умолчанию раньше называлась master, сейчас — main. У меня создалась main. Важно для совпадения с удалённым репозиторием.
9. git log показывает хеш коммита, автора, дату и сообщение.
10. Если не сделать git add перед commit — изменения не попадут в коммит и останутся как "not staged" в git status.
