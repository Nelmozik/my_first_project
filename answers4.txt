Ответы на вопросы для самоконтроля
1. Какое основное свойство CSS включает Flexbox и что происходит с дочерними элементами после его применения?
Flexbox включается свойством `display: flex` (или `display: inline-flex`), применённым к контейнеру. После этого все непосредственные дочерние элементы контейнера автоматически становятся **flex-элементами**: они выстраиваются в одну строку (по умолчанию по горизонтали), перестают учитывать `float`, `clear` и вертикальные margin-схлопывания, а их размеры начинают подчиняться flex-свойствам (`flex-grow`, `flex-shrink`, `flex-basis`) вместо обычного блочного/строчного потока.
2. В чём разница между justify-content и align-items? Приведите примеры использования каждого.
- `justify-content` выравнивает элементы вдоль **главной оси** (main axis) — то есть вдоль направления, заданного `flex-direction`. Пример: `justify-content: space-between` — равномерно распределяет элементы меню по всей ширине шапки, как в `.nav` из проекта.
- `align-items` выравнивает элементы вдоль **поперечной оси** (cross axis) — перпендикулярно направлению `flex-direction`. Пример: `align-items: center` — вертикально центрирует иконку, текст и кнопку внутри строки навигации одинаковой высоты.
Проще говоря: `justify-content` — «вдоль ряда», `align-items` — «поперёкряда».
3. Что делает свойство flex-direction и какие значения может принимать? Как оно влияет на основную ось?
`flex-direction` задаёт направление, в котором располагаются flex-элементы внутри контейнера, и тем самым определяет, что именно считается главной осью:
- `row` (по умолчанию) — элементы идут слева направо, главная ось горизонтальна;
- `row-reverse` — элементы идут справа налево;
- `column` — элементы идут сверху вниз, главная ось становится вертикальной;
- `column-reverse` — элементы идут снизу вверх.
Когда направление меняется на `column`, `justify-content` и `align-items` фактически «меняются местами» по смыслу, так как главная и поперечная оси разворачиваются на 90°.
4. Объясните значение трёх свойств в сокращённой записи flex: 1. Что означают flex-grow, flex-shrink и flex-basis?
Запись `flex: 1` — это сокращение для `flex-grow: 1; flex-shrink: 1; flex-basis: 0%`.
- `flex-grow` — коэффициент, показывающий, насколько элемент может **вырасти**, забирая свободное пространство контейнера, относительно других элементов;
- `flex-shrink` — коэффициент, показывающий, насколько элемент может **сжаться**, если места в контейнере не хватает;
- `flex-basis` — базовый (стартовый) размер элемента до применения роста/сжатия — по сути, аналог `width` (или `height` при column-направлении).
В проекте `.card { flex: 1 1 220px; }` означает: карточки могут расти и сжиматься, но стартуют с ширины 220px — благодаря этому карточки в `.cards` растягиваются равномерно на широком экране.
5. Как работает свойство flex-wrap и в каких случаях его следует использовать?
По умолчанию (`flex-wrap: nowrap`) все flex-элементы пытаются поместиться в одну строку, сжимаясь при нехватке места. Свойство `flex-wrap: wrap` разрешает элементам **переноситься на новую строку**, если они не помещаются по ширине контейнера. Это стоит использовать, когда элементов много или их суммарная минимальная ширина превышает ширину контейнера на маленьких экранах — как в блоке `.gallery__wrap`, где фотографии студии переносятся на новую строку без единого медиа-запроса.
6. Чем отличается align-content от align-items и когда применяется каждое из этих свойств?
- `align-items` выравнивает **отдельные элементы** внутри их строки по поперечной оси.
- `align-content` выравнивает **сами строки** (если их несколько, то есть контейнер многострочный благодаря `flex-wrap: wrap`) относительно друг друга внутри контейнера по поперечной оси.
`align-content` не даёт эффекта, если в контейнере всего одна строка элементов — в этом случае работает только `align-items`.
7. Как свойство order влияет на отображение элементов и в каких практических ситуациях оно может быть полезно?
`order` задаёт **визуальный порядок** flex-элемента внутри контейнера, не изменяя порядок в HTML-разметке. По умолчанию у всех элементов `order: 0`, элементы с меньшим значением показываются раньше. Это полезно, когда нужно изменить порядок отображения блока на разных разрешениях экрана (например, переместить кнопку «Купить» выше описания на мобильном), либо — как в разделе `.process__steps` проекта — сохранить логичный порядок разметки в коде (для доступности/SEO), но показать шаги пользователю в нужной визуальной последовательности через инлайн-стили `order`.
8. Что такое «осевая линия» (main axis) и поперечная ось (cross axis) в Flexbox и как они связаны с flex-direction?
Главная ось (main axis) — это направление, вдоль которого flex-контейнер располагает элементы; она задаётся свойством `flex-direction`. Поперечная ось (cross axis) всегда перпендикулярна главной. При `flex-direction: row` главная ось горизонтальна, а поперечная — вертикальна; при `flex-direction: column` — наоборот. Именно от этой связи зависит, какое из свойств (`justify-content` или `align-items`) отвечает за горизонтальное, а какое — за вертикальное выравнивание в конкретном случае.
9. Как создать адаптивный макет с помощью Flexbox без использования медиа-запросов? Приведите пример.
Достаточно комбинации `flex-wrap: wrap` и гибких `flex-basis` значений: элементы сами переносятся на новую строку, когда не помещаются, а их ширина «плавает» между минимальным и максимальным значением благодаря `flex-grow`/`flex-shrink`. Пример из проекта:
css
.gallery__wrap {
  display: flex;
  flex-wrap: wrap;
  gap: 16px;
}
.gallery__item {
  flex: 1 1 180px;
  max-width: 240px;
}
Здесь каждая карточка старается быть не меньше 180px, растягивается на свободное место, но не шире 240px, и при нехватке ширины переносится на новую строку — макет подстраивается под экран без единого `@media`.
10. Какие преимущества даёт использование gap вместо margins для создания промежутков между flex-элементами?
- `gap` задаёт отступ **только между** элементами, не добавляя лишний отступ по внешнему краю контейнера (как это происходит с margin у крайних элементов, если не сбрасывать его отдельно).
- Не требует псевдоклассов вроде `:last-child { margin-right: 0; }` для устранения лишнего отступа у последнего элемента.
- Корректно работает при переносе строк (`flex-wrap: wrap`), создавая одинаковый отступ и по горизонтали, и по вертикали — margin в этом случае пришлось бы настраивать отдельно для обоих направлений.
- Код становится короче и предсказуемее, особенно в сетках карточек и меню, как `.cards`, `.nav__menu` или `.site-footer` в этом проекте.
