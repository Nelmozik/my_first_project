1. Какие HTML5-атрибуты используются для клиентской валидации и какую функциональность они предоставляют?
`required` — поле обязательно; `minlength`/`maxlength` — ограничения длины текста; `min`/`max` — границы чисел и дат; 
`step` — шаг значения; `pattern` — регулярное выражение, которому должно соответствовать значение;
`type` (`email`, `url`, `tel`, `number`, `date`) — проверка формата и подходящая клавиатура на мобильных; 
`placeholder` и `autocomplete` — подсказки. Браузер сам формирует состояние валидности (`ValidityState`), доступное через `checkValidity()` и псевдоклассы `:valid`/`:invalid`.

2. В чем разница между novalidate атрибутом формы и отключением валидации через JavaScript?
Атрибут `novalidate` на `<form>` отключает только встроенные всплывающие подсказки браузера и автоматическую блокировку отправки. 
Сами ограничения (`required`, `pattern` и т. д.) остаются в разметке, и их можно проверить из JS методом `checkValidity()` — именно так сделано в работе: форма с `novalidate`, а сообщения об ошибках формирует `script.js`.
«Отключение валидации через JavaScript» — это просто отсутствие JS-проверок или вызов `preventDefault()`: если при этом `novalidate` не стоит, браузерная проверка всё равно сработает. 
Важно, что любая клиентская валидация обходится, поэтому на сервере проверка обязательна.

3. Как правильно связать <label> с полем ввода и почему это важно для доступности?
Два способа: явный — `<label for="email">` и `<input id="email">` с одинаковым значением; неявный — поле находится внутри `<label>`.
В работе используется явная связь (для текстовых полей) и вложенные поля внутри label (для radio/checkbox).
Это важно, потому что скринридер зачитывает подпись при фокусе на поле, а клик по тексту подписи активирует поле — это увеличивает область нажатия (особенно полезно для маленьких чекбоксов на телефоне). 
Placeholder заменять label нельзя: он исчезает при вводе и плохо читается.

4. Какие типы полей input наиболее подходят для разных видов данных (email, телефон, пароль и т.д.)?
`type="text"` — имя, фамилия; `email` — адрес почты (проверка формата, клавиатура с @); `tel` — телефон (цифровая клавиатура); 
`password` — пароль (символы скрыты); `date` — дата (календарь, ограничения `min`/`max`); `number` — числа; `url` — ссылки; `radio` — один вариант из группы (пол);
`checkbox` — несколько флагов (интересы, согласие); `<select>` — выбор из списка (страна); `<textarea>` — многострочный текст («О себе»).

5. Как работает валидация с помощью pattern атрибута и в каких случаях его следует использовать?
`pattern` содержит регулярное выражение, с которым должно полностью совпадать значение (браузер сам добавляет привязку к началу и концу строки). 
Если значение не подходит, у поля устанавливается `validity.patternMismatch`, и поле становится `:invalid`.
Пример из работы для телефона: `\+\d{1,3}\s?\(\d{1,5}\)\s?\d{1,3}-\d{2}-\d{2}` пропускает `+7 (999) 999-99-99`. Для пароля: `(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}` — как минимум по одной строчной, заглавной букве и цифре и длина от 8.
Использовать стоит, когда формат нельзя выразить типом поля: телефон, индекс, код, сложные пароли. 
Для email лучше `type="email"`. Всегда нужно давать пользователю понятную подсказку формата, так как сообщение по умолчанию неинформативно.

6. Какие события JavaScript используются для реализации валидации в реальном времени и почему?
`blur` — потеря фокуса: хороший момент для проверки, так как пользователь закончил ввод поля, и ошибку не показывают, пока он ещё печатает.
`input` — каждое изменение значения: используется для скрытия ошибки сразу после исправления, для счётчика символов и проверки подтверждения пароля.
`change` — для `select` и `checkbox`. `submit` — финальная проверка всех полей перед отправкой, где вызывается `preventDefault()` при ошибках. 
`reset` — очистка состояния ошибок. Событие `focus` используется реже: например, для подсказок.
7. Как обеспечить доступность сообщений об ошибках для пользователей скринридеров?
Связать сообщение с полем через `aria-describedby="emailError"`; у контейнера ошибки поставить `aria-live="polite"`, чтобы сообщение зачитывалось при появлении;
при ошибке выставлять полю `aria-invalid="true"`; после неудачной отправки переводить фокус на первое некорректное поле (в работе — `firstInvalid.focus()`); 
итоговое сообщение выводить в области `role="status"`. Нельзя передавать ошибку только цветом — рядом всегда есть текст; у обязательных полей кроме `*` есть атрибут `required`.

8. В чем преимущества использования fieldset и legend для группировки полей формы?
`<fieldset>` объединяет связанные поля (личные данные, безопасность, дополнительная информация), а `<legend>` задаёт название группы. 
Для скринридера название группы озвучивается при входе в неё, и это даёт контекст (особенно для radio-кнопок: «Пол: мужской»). 
Для всех — визуальная структура формы и возможность отключить всю группу атрибутом `disabled`. Это семантически правильнее, чем набор `<div>` с заголовками.

9. Как реализовать кастомную валидацию для сложных случаев (например, подтверждение пароля)?
Сравнивать значения нужно в JS: в работе функция `validatePasswordMatch()` сравнивает `password.value` и `confirmPassword.value`, при несовпадении показывает «Пароли не совпадают» и возвращает `false`.
Вызывается при вводе в любое из двух полей и при отправке. Можно использовать `setCustomValidity('сообщение')` — тогда поле становится `:invalid` и работает с `checkValidity()`; при корректных данных нужно вызвать `setCustomValidity('')`. 
Аналогично проверяются зависимые поля (дата окончания не раньше даты начала), уникальность логина (запрос на сервер) и т. п.

10. Какие методы CSS используются для визуального отображения состояний валидности/невалидности полей?
Псевдоклассы `:valid` и `:invalid`, `:required`/`:optional`, `:focus`, `:focus-visible`, `:placeholder-shown`, `:user-invalid` (новый).
В работе: `input:invalid:not(:focus):not(:placeholder-shown)` — красная рамка, `input:valid:not(:focus):not(:placeholder-shown)` — зелёная (условия нужны, чтобы пустое поле не краснело до ввода).
Из JS добавляется класс `.error` — красная рамка, розовый фон, анимация `shake`. Также используются `:checked + .radio-custom` для кастомных radio/checkbox и `prefers-reduced-motion` для отключения анимации.
