1. Что такое Viewport meta tag и почему он важен для адаптивного дизайна?
Viewport meta tag — это тег `<meta name="viewport" content="width=device-width, initial-scale=1.0">` в `<head>`. Он говорит мобильному браузеру, какой ширины считать область отображения страницы и какой масштаб использовать при загрузке.
Без него смартфон считает страницу «десктопной» шириной около 980 px и уменьшает её целиком, поэтому медиа-запросы по `max-width: 768px` не срабатывают и текст получается мелким. С `width=device-width` ширина viewport равна реальной ширине экрана в CSS-пикселях, и адаптивные правила начинают работать.

2. Какие основные подходы к созданию адаптивных макетов вы использовали в работе (Fluid, Adaptive, Responsive)?
Fluid (резиновый) — размеры заданы в относительных единицах: у контейнера `width: 100%; max-width: 1200px`, у изображений `max-width: 100%`, у сетки `1fr`.
Adaptive (адаптивный в узком смысле) — несколько фиксированных макетов под определённые ширины. В работе этот подход используется частично: при ширине 1024, 768 и 480 px резко меняются число колонок и вид навигации.
Responsive (отзывчивый) — сочетание двух предыдущих: гибкая сетка + изображения + медиа-запросы. В итоге в работе реализован именно Responsive: макет плавно тянется между брейкпоинтами и перестраивается на них.

3. Как работает Mobile First подход и в чем его преимущества перед Desktop First?
Mobile First — это когда базовые стили пишутся для маленьких экранов, а для больших они дополняются медиа-запросами с `min-width` (`@media (min-width: 768px) { ... }`). Desktop First — наоборот: базовые стили для десктопа, а для малых экранов используются `max-width`.
Преимущества Mobile First: мобильное устройство получает только нужный минимум CSS и не переопределяет десктопные правила; приходится думать о главном контенте; проще наращивать сложность, чем убирать её. Кроме того, поисковики индексируют мобильную версию в первую очередь. В этой практической работе (по заданию) использован Desktop First с `max-width`; для нового проекта предпочтителен Mobile First.

4. Какие единицы измерения наиболее предпочтительны для адаптивной верстки и почему (%, rem, em, vw/vh)?
Нет одной «лучшей» единицы, каждая подходит для своей задачи:
`%` — ширина блоков относительно родителя (`width: 100%`). `rem` — относительно размера шрифта `<html>`: удобно для шрифтов и отступов, потому что их можно масштабировать на брейкпоинтах, меняя только `html { font-size }` (в работе: 16px → 15px → 14px); а также уважает настройки браузера пользователя. `em` — относительно шрифта текущего элемента, удобно для компонентов, которые должны масштабироваться вместе с собственным текстом (кнопки). `vw/vh` — доля ширины/высоты окна, подходят для крупных заголовков и секций на весь экран, но в чистом виде не уважают настройки пользователя, поэтому их комбинируют с `clamp()`.
Пиксели лучше оставлять для тонких деталей: границы 1px, радиусы, тени.

5. Как функция clamp() помогает создавать адаптивную типографику?
`clamp(min, preferred, max)` возвращает значение `preferred`, но не меньше `min` и не больше `max`. Например, `font-size: clamp(1.75rem, 5vw, 2.75rem)` в заголовке hero: на узком экране размер не опускается ниже 1.75rem, на широком не превышает 2.75rem, а между ними плавно растёт вместе с шириной окна.
Благодаря этому типографика становится «текучей» без набора медиа-запросов под каждый брейкпоинт: один декларативный CSS-вызов заменяет несколько правил.

6. Какие основные брейкпоинты вы использовали и как определили эти значения?
В работе использованы четыре диапазона: более 1024px — десктоп (3 колонки, боковая панель справа); до 1024px — планшет (2 колонки, боковая панель переходит под статью); до 768px — мобильные (бургер-меню, уменьшенный базовый шрифт); до 480px — маленькие телефоны (1 колонка, компактные отступы).
Значения взяты из типичных ширин устройств, но главное правило: брейкпоинт ставится там, где макет начинает «ломаться» — это проверялось, плавно сжимая окно в режиме адаптивного дизайна в DevTools. Привязка к конкретным моделям телефонов нежелательна, потому что устройств слишком много.

7. Как медиа-запросы @media помогают создавать адаптивные стили? Приведите пример синтаксиса.
Медиа-запрос применяет блок CSS только если выполняется условие: ширина окна, ориентация, плотность пикселей, предпочтения пользователя и т. д. Это позволяет менять сетку, размеры и видимость элементов под разные устройства.
Пример из работы:
```css
@media (max-width: 768px) {
  .nav-toggle { display: block; }   /* показываем бургер */
  .nav-menu   { display: none; }    /* прячем меню до клика */
}
```
8. В чем разница между max-width и min-width в медиа-запросах и когда использовать каждый?
`max-width: 768px` — правила действуют, когда ширина окна 768px и меньше («до»). `min-width: 768px` — когда ширина 768px и больше («от»).
`max-width` используется в подходе Desktop First (базовые стили для десктопа, далее — «сужающие» правила). `min-width` — в Mobile First (базовые стили для телефона, далее — «расширяющие» правила). Смешивать оба подхода в одном файле без необходимости не стоит: порядок правил и каскад становится запутанным.

9. Как сделать изображения адаптивными и какие CSS-свойства для этого используются?
Минимум — `img { max-width: 100%; height: auto; }`: картинка не выходит за пределы родителя и сохраняет пропорции. В работе у изображения в статье задано `width: 100%; height: auto`. Чтобы избежать скачков вёрстки при загрузке, в HTML указывают атрибуты `width` и `height`.
Дополнительно: `object-fit: cover` для заполнения блока с обрезкой, `aspect-ratio` для фиксированных пропорций, а в HTML — `srcset`/`sizes` и `<picture>` для выдачи разных файлов под разные экраны и форматы (WebP/AVIF), `loading="lazy"` для отложенной загрузки.

10. Какие инструменты браузера помогают тестировать и отлаживать адаптивный дизайн?
В DevTools (F12): режим адаптивного дизайна (Ctrl/Cmd+Shift+M) — можно задать любую ширину или выбрать устройство из списка; панель Elements/Styles — видно, какие медиа-запросы сработали, и можно править значения вживую; Computed — итоговые размеры; Network throttling — эмуляция медленного интернета; Rendering — эмуляция `prefers-color-scheme`, `prefers-reduced-motion`; Lighthouse — аудит (в том числе мобильной версии).
Дополнительно имеет смысл проверить на реальном устройстве, так как эмуляция не повторяет поведение сенсорного экрана и системной клавиатуры.
